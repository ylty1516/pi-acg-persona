# pi-acg-persona 设计规格

日期：2026-10-28
状态：已定稿

## 1. 目标

一个**公开**的 GitHub 仓库（`pi-acg-persona`，Description：`pi agent 的二次元人设`），存放 pi 的全局「二次元人设卡」：写一次，之后所有 pi 对话窗口自动生效，不需要每次重复交代身份、语气和行为偏好。同时，格式足够清楚，让别人也能照着写自己的人设卡。

## 2. 非目标

- 不做子代理人设卡（`agents/*.md`，那种只在被 spawn 时生效）
- 不做 schema 校验器、不做人设卡 lint
- 不做多角色自动编排 / 按项目自动切人设
- 不做英文版
- 不预置任何受版权保护的具体角色（示例卡为原创角色）

## 3. 需求来源（来自对话）

1. 用途：pi 的**二次元**人设卡，写一次全局常驻
2. 核心诉求：「记下来以后所有的对话窗口都用这一套人设」
3. 工具负责「持久化 + 可切换 + 可回滚」；人设内容由用户提供
4. 仓库**公开**，需对外可用：README 自解释、示例卡、License

## 4. 关键技术事实（已从源码/文档确认）

pi 的 system prompt 由若干命名段拼成（`dist/core/system-prompt.js`）：

| 来源文件 | 注入段 | 覆盖规则 |
|---|---|---|
| `<agent-dir>/APPEND_SYSTEM.md` | `<addendum>` | 项目级 `.pi/APPEND_SYSTEM.md` 存在时**整份顶掉，不合并** |
| `<agent-dir>/AGENTS.md` | `<project_context>`，前缀 `Project-specific instructions and guidelines:` | 永远累加 |

- `agent-dir` 由 `PI_CODING_AGENT_DIR` 决定，未设时默认 `~/.pi/agent`
- 本机该目录下 `APPEND_SYSTEM.md` **已存在**，内容为三段：语言与沟通 / 日常编码习惯 / 工具使用
- 改完需 `/reload` 生效

## 5. 设计决策

### 5.1 人设装在 `APPEND_SYSTEM.md`（方案 A）

理由：
- 人设是**身份层**，语义上属于 system prompt 的 addendum，不是"项目指令"
- 单一文件 = 换人设/回滚都是文件级操作，不污染 `AGENTS.md` 里的工程规范
- 决策可逆成本极低：人设卡内容与安装目标无关，日后想改走双写方案只需改 `install.ps1`
- 不硬编码本机路径：脚本用 `PI_CODING_AGENT_DIR` / `$HOME\.pi\agent` 解析，公开可用

已知代价（接受，README 写明）：项目若自带 `.pi/APPEND_SYSTEM.md`，全局人设被整份顶掉。

### 5.2 组合式：基础行为层 + 角色身份层

因为 `APPEND_SYSTEM.md` 是**整份替换**，若每张人设卡都自带公共约定，改一次基础要改 N 个文件。

=> 拆两层，安装时拼接：

```
base/behavior.md    (公共基础：语言、编码习惯、工具使用)
        +
personas/<name>.md  (角色身份：我是谁、语气、边界、工作方式)
        ↓ install.ps1 拼接
<agent-dir>/APPEND_SYSTEM.md
```

`base/behavior.md` 初始内容 = 现有 `APPEND_SYSTEM.md` 的三段（迁入仓库成为唯一真源）。

### 5.3 仓库结构

```
pi-acg-persona/
├── README.md                 # 是什么 / 原理 / 怎么装 / 怎么切 / 怎么回滚 / 风险
├── LICENSE                   # MIT
├── .gitignore                # .backup/
├── base/
│   └── behavior.md           # 公共基础行为层
├── personas/
│   └── example.md            # 示例人设卡（原创角色，供复制改造）
├── persona.template.md       # 空白骨架
├── install.ps1               # 安装/切换/状态/卸载
└── docs/superpowers/specs/2026-10-28-pi-acg-persona-design.md
```

### 5.4 人设卡骨架（`persona.template.md`）

纯 Markdown（原样注入 system prompt），**不使用 YAML frontmatter**（避免噪音），首行 `# 人设：<名字>`。

章节：

1. **身份** — 我是谁、服务谁、什么定位
2. **语气与表达** — 自称、称呼、语速篇幅、口癖（限 2 个）、要避免的腔调
3. **二次元浓度与出戏规则** — 这是本仓库特有段：腔调只作用于**叙述层**；代码、命令、报错、API 名、路径**一律不角色扮演**
4. **判断原则** — 不确定 / 技术事实与角色感冲突 / 用户犯错时怎么取舍
5. **工作方式** — 探索→计划→执行的节奏、汇报方式、主动程度
6. **分场景行为** — 写代码 / 评审 / 解释概念 / 被质疑 / 翻车时
7. **明确禁止** — 反模式清单

### 5.5 `install.ps1` 契约

```
.\install.ps1 -List                # 列出 personas/*.md 的 id
.\install.ps1 -Use <name>          # 备份 → 拼接 → 写入 → 打印摘要
.\install.ps1 -Status              # 报告当前生效的是哪张卡
.\install.ps1 -Uninstall           # 备份 → 删除 → 打印回滚提示
.\install.ps1                      # 打印帮助，不做任何写操作
```

- 目标目录：`$env:PI_CODING_AGENT_DIR` 优先，否则 `$HOME\.pi\agent`
- 备份：`.backup/APPEND_SYSTEM.<yyyyMMdd-HHmmss>.md`（入库 .gitignore）
- 备份失败则中止，绝不覆盖
- 写入 UTF-8 **无 BOM**，换行 LF
- 生成标记（不含时间戳，保证 `-Status` 哈希稳定）：

```
<!-- generated by pi-acg-persona : <name> -->
```

`-Status` 判定：文件不存在 → 未安装；有标记且哈希匹配 → 当前生效 `<name>`；有标记但哈希不符 → 已手改；无标记 → 非本仓库管理。

### 5.6 与现有 `AGENTS.md` 的分工

- `APPEND_SYSTEM.md`（本仓库）= **怎么行为**：身份、语气、判断原则
- `AGENTS.md` = **什么规范**：工程约定、工作区路径、已装能力清单

轻微重叠（中文回复、不确定先确认）不冲突，README 写明；人设卡内加「冲突时以项目 AGENTS.md 的具体规范为准」条款。

## 6. 验收标准

1. `git clone` 后 `.\install.ps1 -Use <name>` 一条命令生效
2. `/reload` 后新会话的 `<addendum>` 段出现人设内容
3. 覆盖前必生成备份，`-Uninstall` 能回到无人设状态
4. `-Status` 能正确识别当前生效的人设（含「已手改」态）
5. README 让人不看我也能完成安装、切换、回滚
6. 脚本不硬编码任何本机路径

## 7. 风险

| 风险 | 处理 |
|---|---|
| 项目级 `.pi/APPEND_SYSTEM.md` 顶掉全局人设 | README 写明 |
| 人设与 `AGENTS.md` 指令打架 | 卡内加「以项目 AGENTS.md 的具体规范为准」 |
| 腔调压过专业性 | 模板强制「出戏规则」段 |
| 人设过长稀释权重 | README 给「建议 ≤ 150 行」提示 |
